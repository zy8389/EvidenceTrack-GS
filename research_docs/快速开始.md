# 快速开始：从 CPU 自检到第一轮 A1 / SelfRender / B

本教程有两类命令：overlay 目录的 CPU 自检可直接在普通机器执行；真实训练必须先装配固定版本 GeoTrack-GS，在带 CUDA 的服务器执行。数据、预训练权重及上游完整仓库不在压缩包内，不能把代码包解压后直接当作已经配置好的服务器环境。

## 1. 阅读与目录

先读“方案复审与理论说明.md”和“变更与验证边界.md”，再看 paper/main_v2.pdf。code/patches/phase2_1_integrity.patch 是从固定原仓库提交起的累计补丁，只应用一次。不要再叠加 MVP、Phase2、旧 Phase2.1 补丁。

code/diffusion_guidance 和 code/geometric_constraints 是可读的研究实现；code/tools 是 track、导出、Difix 缓存、诊断、统计工具；code/scripts 是装配和分阶段运行入口。validation/ 是历史 CPU 日志，不是当前修复或服务器结果。

## 2. 普通机器先跑 CPU

在代码包 code 目录创建隔离 Python 环境并安装 CPU 所需依赖。下面的宽松依赖范围是测试入口，不是经过验证的 CUDA 环境锁。本轮修复遵照用户要求没有运行测试；已有 `validation/` 日志属于更早源码快照，不能当作当前修复通过证据。

```bash
cd GeoTrack_Diffusion_Research_Package/code
python -m venv .venv-cpu
source .venv-cpu/bin/activate
pip install -r requirements-cpu.txt
bash scripts/run_cpu.sh
```

Windows 使用 .venv-cpu\Scripts\activate；后续 bash 脚本建议在 WSL 或 Linux 执行。`synthetic_recovery.json` 应包含 `passed=true`，CPU 命令必须以零状态退出。历史快照曾记录 23 个 pytest 与 11 个 smoke，但当前测试数量和结果必须以重新运行后的输出为准。smoke 中的 FakeDifix 不是实际模型推理，不需要下载扩散权重。

## 3. 一键装配完整工程

下面只在全新的目标目录执行；装配脚本会拒绝覆盖已有项目。原仓库需要当前网络或你的 GitHub 访问权限。

```bash
bash scripts/bootstrap.sh /workspace/GeoTrack-GS-research-v2
cd /workspace/GeoTrack-GS-research-v2
```

脚本固定提交，校验累计补丁，复制新增源码，并检查已知结构后修改 checkpoint、投影与保存顺序。累计补丁必须来自 AST 修改前的固定上游基线；复制后的 tools 已经带有严格标定调用，AST 不会再次插入。遇到 git apply 或 AST 结构报错，停止处理；不要使用 fuzzy apply，也不要跳过 guard。脚本结束只表示源码装配完成，**不执行**语法检查、CPU、CUDA 或训练验证。

随后按原仓库对应提交的环境说明创建 CUDA 环境，构建它自带的两个扩展，不要拿标准 3DGS 的同名模块替换。

```bash
pip install ./submodules/diff-gaussian-rasterization-confidence
pip install ./submodules/simple-knn
PYTHONPATH=. python -m compileall -q diffusion_guidance tools
PYTHONPATH=. python tools/collect_environment.py --output server_environment.json
```

本次没有在 GPU 上验证哪组 torch/CUDA/编译器组合最佳，因此不提供虚构的“已锁定可用版本”。保留原仓库环境作为起点，记录实际成功安装版本。

## 4. 准备数据与输出目录

场景需要 images/ 和 sparse/0/ 的给定相机文件，使用已去畸变图像。第一次只跑 fern 开发场景，固定3图、seed1。Fern 和 room 是 `development`，其余六个 LLFF 场景是 `confirmatory`。输出路径建议包含场景名、视角数与 seed，避免结果覆盖。

```bash
export SCENE=/datasets/LLFF/fern
export DATASET=LLFF
export RUN=/experiments/fern_v3_seed1_research_v2
export SEED=1
export VIEWS=3
export HOLDOUT=8
bash research_scripts/run_stage.sh env
bash research_scripts/run_stage.sh tracks
bash research_scripts/run_stage.sh projection
bash research_scripts/run_stage.sh pseudo-live
bash research_scripts/run_stage.sh smoke
```

tracks 生成 split/source_images.txt、split/heldout_images.txt 和 tracks_source_only.h5。audit 保留最少32条有效轨迹，否则停止并检查数据、尺度、重叠、去畸变和对应关系，不偷偷改成读取全场景 Track。projection 比较 H5 与 live Scene 的 original/training 像素路径；pseudo-live 在 A0 前验证真实 pseudo-camera provenance；smoke 检查训练中 geometry gradients、关联与覆盖的有效性。投影门禁依赖 H5 anchors，因此 tracks 必须先于 projection。

## 5. 生成共同 A0 并做恢复测试

```bash
bash research_scripts/run_stage.sh A0
bash research_scripts/run_stage.sh recover
bash research_scripts/run_stage.sh export
bash research_scripts/run_stage.sh pseudo-audit
bash research_scripts/run_stage.sh self-manifest
```

A0 必须重新训练，不能沿用旧的不完整 checkpoint。新的 10k A0 checkpoint 内嵌 `controlled_checkpoint_provenance_v2`，锁定 scene、Track、source 图像字节、校准后训练相机、seed、严格几何参数和完整共同训练协议。A1/SelfRender/B 在首个训练更新前把该内嵌对象与当前输入逐项核对；10k 后三条 continuation 都冻结拓扑，source RGB 与 Track 的训练设置相同。recovery 只在内存中扰动并恢复 checkpoint，不将扰动结果保存成正式训练结果。

## 6. 在独立环境生成 Difix 缓存

克隆官方 nv-tlabs/Difix3D，按该仓库安装模型依赖，选择并固定实际运行的代码提交。使用 nvidia/difix_ref 的不可变40字符模型 revision，不要将 main 当成可复现版本。以下环境变量值必须由实际下载的版本填入；它们不是可编造的论文参数。

```bash
export DIFIX_REPO=/workspace/Difix3D
export DIFIX_MODEL_REVISION=实际选定的40字符模型提交
bash research_scripts/run_stage.sh cache
```

cache 会记录输入/参考图/输出哈希、模型和代码版本，并重复首张推理检查像素或有限容差一致性。关闭旧缓存跳过功能，避免前后实验混用。输出显式恢复为输入完整画幅尺寸；改变 resize 策略必须整体重新生成缓存，并作为方法变更记录。

## 7. 回到 GS 环境执行 A1、SelfRender 与 B

```bash
bash research_scripts/run_stage.sh A1
bash research_scripts/run_stage.sh SelfRender
bash research_scripts/run_stage.sh B
bash research_scripts/run_stage.sh pair-self
bash research_scripts/run_stage.sh pair-b
bash research_scripts/run_stage.sh pair-pseudo
```

pair audit 必须看到相同起点哈希和 A0 provenance digest、相同2000次 source序列、相同的完整共同训练参数、相同 source 图像字节清单、相同校准后训练相机清单，以及39次pseudo调用和32个unique views。Pseudo manifest 的每条记录绑定 A0 checkpoint 内嵌 provenance digest；SelfRender 和 B 的 camera keys/schedule 还必须逐条相同，并且两者都必须启用 strict frozen-cache 校验。v5 审计显式记录已经严格验证的 pseudo 方法；省略 pseudo 验证时审计不能通过。它还会重新读取 A1/SelfRender/B 对应的精确 12k checkpoint，核对文件 SHA256、方法角色、render state、父 A0 路径/哈希/provenance lineage，以及 B/SelfRender 的 manifest 路径/哈希、camera-pool digest 和 target kind，并把 final checkpoint 纳入完整输入文件清单。路径不是规范绝对路径、SHA256 不是原生小写64位字符串或任一文件变化时均失败。Held-out 记录使用 v2 schema，paired manifest/sidecar/association 使用 v4 schema并传播 A1/B final provenance digest。三个对照的解释固定为：SelfRender−A1 是通用 pseudo supervision，B−SelfRender 是 diffusion target replacement，B−A1 是总分支效应。`passed=true` 只代表实验条件可配对，不代表 B 的质量提高。每个 scene/seed 都要使用自己的 pair_id 和审计JSON。

## 8. 单独做身份诊断

先从 A1 导出 held-out GS 图，再在 Difix 环境做增强，然后切到 DINO 环境。DINOv2 需要本地固定提交的官方 clone，并记录预训练权重文件哈希。禁止使用可变的远程 torch.hub 默认仓库悄悄切版本。

```bash
bash research_scripts/run_stage.sh evidence-export-a1
bash research_scripts/run_stage.sh evidence-export-b
bash research_scripts/run_stage.sh evidence-cache-a1
bash research_scripts/run_stage.sh evidence-cache-b
bash research_scripts/run_stage.sh identity-manifest
export DINOV2_REPO=/workspace/dinov2
export DINOV2_WEIGHT_PATH=/workspace/weights/dinov2_vits14.pth
bash research_scripts/run_stage.sh identity-a1
bash research_scripts/run_stage.sh identity-b
bash research_scripts/run_stage.sh identity-report
```

先看 paired_report.json，而不是只看成功样本平均误差。重点检查 Difix 相对 GS 的收益、相对 ProjectionOnly 的收益、有效 hard negative 的身份 margin、PCK及failure rate。Real Target 是有特权的参考诊断，不是数学上界。shift-recovery 表里使用了 GT-inside-window 的部分不能当主鲁棒性结论。

## 9. 导出真实指标并汇总

```bash
bash research_scripts/run_stage.sh metrics
bash research_scripts/run_stage.sh integrity
```

`metrics` 从 `$RUN/A1/train.log`、`$RUN/SelfRender/train.log`、`$RUN/B/train.log` 生成三份严格的两臂 CSV。`integrity` 重新生成配对审计与指标并核对当前 Track、投影上下文、pseudo manifest、checkpoint、Difix 和身份诊断绑定；输出只代表当前一个 scene/seed，且明确记录 `aggregate_performed=false`。工具不会补齐没有跑过的值；`geometry_error` 保留 NR，直到有独立几何结果。

所有场景与 seed 完成后，分别汇集三种 contrast 的同名 CSV，每个汇总文件只保留一个表头，再分别执行 scene-level 对照：

```bash
python tools/aggregate_results.py --csv all_measured_results_a1_b.csv --metric lpips \
  --baseline A1 --treatment B --role confirmatory --output aggregate_a1_b_lpips.json
python tools/aggregate_results.py --csv all_measured_results_a1_selfrender.csv --metric lpips \
  --baseline A1 --treatment SelfRender --role confirmatory --output aggregate_a1_selfrender_lpips.json
python tools/aggregate_results.py --csv all_measured_results_selfrender_b.csv --metric lpips \
  --baseline SelfRender --treatment B --role confirmatory --output aggregate_selfrender_b_lpips.json
```

差值按 treatment−baseline 定义，所以 LPIPS 越低越好时负值是改善，PSNR 越高越好时正值是改善。Fern 的单 scene/seed integrity 结果不是聚合；一个场景不会产生可解释的跨场景置信区间，也不能把三个 seed 或许多 track 当作许多独立场景。

## 10. 常见停止条件

若所有 track 被拒绝，先查相机模型、单位、RGB分辨率和匹配，而不是切换full COLMAP membership。若代码声称几何loss成功但没有梯度，停在P0。若任一 continuation pair 的起点哈希、严格几何配置或 source 序列不同，重跑该对实验。若输出图大小不同，重建缓存及诊断而不是改标签来凑尺寸。若B没有优于SelfRender，保留负结果且不声称冻结Difix target替换有效；若B没有优于A1，则同时不能声称冻结Difix分支存在总收益。即使B优于SelfRender，在非生成增强对照完成前也不声称差异来自扩散机制独有作用。不得增删失败场景。若正确身份与错误身份差不多，不声称Track identity具有贡献。

每完成一个实验，将机器日志或JSON的路径填到实验清单“证据文件”一列，再修改状态；不能先把预期结论填成已完成。首次跑通后再扩展到room、seed2/3，然后锁定参数，在其余六个LLFF场景上运行。
